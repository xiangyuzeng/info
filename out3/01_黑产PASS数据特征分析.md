## 二、最重要的一条：低分漏出已经归零，黑产转向「高分 + 丢 token」

集合 A（1,247 条漏出）的 reCAPTCHA 分布：

| token / 分数状态 | 条数 | 占 A |
|---|---|---|
| token 存在，分数 **> 0.3** | 724 | 58.1% |
| token **缺失或空串** | 523 | 41.9% |
| token 存在，分数 **≤ 0.3** | **0** | **0.0%** |

**漏出里已经一条低分都没有了。** 724 条带 token 的漏出，分数分布是 0.5(146) / 0.6(45) / 0.8(343) / 0.9(190)——全是高分。

两个直接结论：

1. **再加任何一条基于 reCAPTCHA 分数的策略，新增召回为 0。** 172、策略3、策略4 已经把低分人群吃干净了，这三条策略是有效的，但它们的增长空间到头了。
2. **段枝宏 2026-09-11 预判的两条突破口都已经发生**，而且是同时发生：
   - 「后续黑产可能不再带 recaptcher 的 token」→ 已占漏出的 **41.9%**；
   - 高分养号 → 已占漏出的 **58.1%**（分数 0.8/0.9 合计 533 条）。

## 四、按「规避成本」给特征排序

段枝宏：「黑产对抗最好的是先利用特征进行对抗」。但特征也分**改起来多贵**：

| 特征 | 改动成本 | 说明 |
|---|---|---|
| App 版本号 | 极低 | 改一个字符串即可；且本轮已证明它与 token 缺失完全重叠，没有独立价值 |
| token 缺失/空 | 极低 | 黑产随时可以补发一个 token（他们本来就有 58% 的请求带高分 token） |
| 设备机型串 | 极低 | UA 可任意伪造 |
| cid | 低 | 换客户端标识需要改包，但不难 |
| 网关 uid | 低 | **实测每天几乎全换**（见下） |
| IP C 段 | 中 | 需要换托管商出口，有成本但做得到 |
| IP 来源国家 | 中 | 同上，且要同时换目标区号组合 |

**🔴 网关 uid 黑名单不可用。** 逐日测算「携带 ≥3 个手机号的 uid」在次日的留存率：

| 日期 | 热点 /24 数 | 次日留存 | 热点 uid 数 | 次日留存 |
|---|---|---|---|---|
| 09-06 | 31 | — | 155 | — |
| 09-07 | 26 | 42% | 145 | **5%** |
| 09-08 | 47 | 21% | 199 | **3%** |
| 09-09 | 42 | 43% | 173 | **3%** |
| 09-10 | 42 | 50% | 142 | **2%** |
| 09-11 | 23 | 70% | 104 | **0%** |
| 09-12 | 25 | 40% | 116 | **2%** |

uid 留存 0–5%，**uid 黑名单在配置完成的第二天就已经失效**。它在回测里能覆盖 84.4% 的漏出，纯粹是因为名单是从同一份数据里拟合出来的（fit-on-self）。本轮**不提 uid 黑名单**。
IP C 段留存 21–70%（中位约 43%），**只有在每日刷新的前提下**才有意义，静态配置同样会快速失效。

## 五、区分力最强、但引擎尚无对应特征的维度

| 维度 | 实测区分力 | 现状 |
|---|---|---|
| **uid 是否只出现在本场景**（SOP §3.4） | A 中 98.4% vs C3 中 **0.0%** | 🔴 引擎无此特征 |
| 设备品牌/机型 | 近乎完美（见 3.6） | 🔴 引擎无 `userAgent` 特征 |
| 同 uid 近 N 分钟关联手机号数 | A 中位 11 vs C3 中位 1 | 🔴 只有 IP 维度的同类特征 |
| 手机号号码合法性 | 已在标注里使用 | 🔴 引擎无此特征 |
| ASN / 机房 IP 标签 | 未量化 | 🔴 无 |

🔴 **「uid 只出现在本场景」这条必须加一句重要警告**：它是本轮观测到的最强区分特征（98.4% vs 0.0%），但这个数字是**用事后数据算出来的**——真实用户请求验证码时，他的 uid 也还没有出现在其它场景，只有在他随后登录之后才有。因此 98.4%/0.0% 的分离度**高估了它的实时表现**，不能据此立策略。若要用，必须由研发给出**请求时刻可判定**的定义（例如「该 uid 历史上是否出现过非本场景请求」），并重新评估对新用户的误伤。

本轮标注里 `ev_api` 含有该字段，为此专门做了敏感性检验：把它从证据里去掉后，24h 召回从 **62.6% 变为 62.2%**，黑产总量 51,734 → 50,169。**召回结论对它不敏感**；受影响的只是「确认黑产 / 高疑似黑产」的置信档位划分。

## 六、波次特征与重跑节奏

下列特征**一定会过期**，不能一次配置长期不管：

- 目标区号组合（`+504` 已消失，`+220` 已升为第一）
- IP C 段名单（日留存中位 ~43%）
- App 版本串（1.3.40 / 1.3.50 这一批随时可改）
- IP 来源国家名单（本轮 8 国，随托管商切换而变）

**建议节奏**：
1. **每日**重跑 `python -m sms_attack.r3_analyze`，比对候选覆盖率与 IP C 段名单，覆盖率下降 >20% 即视为黑产已换波次，当天重出名单。
2. **每周**重跑单字段画像，检查是否出现新的高 lift 取值。
3. **监控告警**（非 RMS）：境外小时请求 >300；境外占比 >90%；upush 境外日发送 >150；**任一在线策略小时命中数连续 2 小时为 0**（特征改名保护——特征名 30 天内改过三次，按名字取数会静默失效）；**境外请求中不带 token 的小时占比**突增。
