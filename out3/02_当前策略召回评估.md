## 一、召回口径（先把分母说清楚）

第一轮流传的「召回 50% 左右」来自 RMS 大盘两块面板相除：已上线策略 1 小时拦截 84 ÷ 低分代理口径 171 ≈ 49%。
**这两个数的分母不是一回事**：84 来自 172（三国 IP 枚举），171 来自 `strategy_aEw2XWL4QIYx`（全量低分，无区号护栏）。该比值不构成召回率，本报告不沿用。

本报告的召回定义：

> **召回率 = 最近 24h 内、非 +1/+86 区号、按 SOP §3.7 至少两类证据判定为「确认黑产 / 高疑似黑产」的请求中，被 REJECT 的比例。**

证据类别按 SOP §3.2 IP/设备聚集、§3.3 手机号风险、§3.4 API 链路异常、以及 OTP 行为四类交叉印证；§3.5 设备指纹在本场景不可得（`did`/`device_id`/`tongdun_device_id` 全为空），按 SOP §3.7「证据不足不得强行归因」不计入。

**三条策略的误伤均为 0 —— 命中样本中没有一条被判为正常用户。** 这与 upush 侧的观测一致：+1 区号填充率全程稳定在 93.0%–97.9%，未受任何影响（`out3/data/06_upush_daily.csv`）。

⚠️ 三条策略的 `准确率` 分别为 92.3% / 93.7% / 94.1%，**均低于 SOP §二 要求的 99.9%**。原因不是误伤，而是「暂无法判断」样本（228/170/183 条）按公式被从分子里扣除：

```
准确率 =（命中样本量 − 风险样本量 − 暂无法判断样本量）÷ 命中样本量
```

若按示范表隐含的口径（只扣风险样本量），三条策略的准确率都是 **100%**。
🔴 **哪一个口径为准，必须先由田志鲔确认**（见 `05_人工确认清单.md` B1）。这不是措辞问题：它直接决定这三条已上线策略在 SOP 意义上是否达标。本场景因设备指纹不可得，约 6%–7% 的命中样本天然无法形成两类证据闭环，严格口径下 99.9% 事实上不可达。

其余 SOP 门槛（观察时长、整体调用量、整体用户量、命中样本量、误伤比例）三条策略**按高风险强拦截策略标准全部达标**。

## 五、召回是否 OK —— 一句话结论

**不 OK。** 召回 62.6%、境外日发送仍约 1,270 条，是 150 条/天目标的 **8.5 倍**；且漏出人群的构成已经变了 —— 低分漏出归零，剩下的 41.9% 不带 token、58.1% 带高分 token，**现有三条分数型策略对这两部分都结构性无效，继续调分数阈值不会有任何新增召回**。

`strategy_bTCEWBZggaAP`（预上线自 2026-08-31）：


它已经用上了 `字段 recaptchaV3Token 不存在 || recaptchaV3Token 等于 ''`，方向是对的，但有两处使它无法作为本轮答案：

1. 前置条件 `同区号近60分钟未携带recaptchaV3token 访问次数 大于 5` 是**区号级聚合计数器**，正是段枝宏 2026-09-11 否掉策略 1/2 的同一类机制（黑产打满阈值后，该区号的正常用户同样被拦）。
2. `version 版本号大于等于 1.4.30` 把本轮 token 缺失漏出的主力（1.3.40 计 289 条、1.3.50 计 114 条、1.4.26 计 26 条，合计占 token 缺失漏出的 82%）全部排除在外。

因此本轮另出候选，不复用这条。
