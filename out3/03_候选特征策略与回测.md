# 候选特征策略与回测（第三轮）

规则一律用引擎自身词汇书写（`t_rms_engine_rule` 实有算子），不用意译。
覆盖率基于集合 A（境外区号 ∧ 非美国IP ∧ PASS，最近24h，1,247 条）与集合 B（境外区号 ∧ PASS，1,504 条）。
误伤一律按**策略自己的命中样本**计算，不按对照组规模计算。

---

## 一、先说三条「看起来很好、实际不能用」的候选

写在最前面，因为它们的回测数字最漂亮，最容易被当成结论。

### ❌ 仅 `cid 包含 105`
覆盖 A **98.7%**。但 C3（OTP 已填充的真实境外用户）里有 **70 条**也是 cid=105。单条上线会直接打掉真实的安卓境外用户。**否决。**

### ❌ `网关uid 黑名单`
覆盖 A **84.4%**，C3 仅命中 3 条，看上去极佳。但热点 uid 的**次日留存率只有 0–5%**（`01_` 第四节实测表），名单配置完成的第二天就已失效。84.4% 是从同一份数据拟合出来的（fit-on-self），不代表任何前瞻性能。**否决。**

### ❌ 新增任何 reCAPTCHA 分数阈值策略
集合 A 中 `分数 ≤ 0.3` 的条数为 **0**。172 / 策略3 / 策略4 已把低分人群吃尽。再加分数型策略，**新增召回为 0**。**否决。**

## 二、入选候选

### 🟢 R3C1 —— token 缺失/空串（正面回应段枝宏的 token 预警）

```
(区号不是1&&区号不是+1&&区号不是86&&区号不是+86)&&cid 包含 105
&&(字段 recaptchaV3Token 不存在||recaptchaV3Token 等于 '') 则 REJECT
```

| 指标 | 数值 |
|---|---|
| 覆盖 A | 518 / 1,247 = **41.5%** |
| 覆盖 B | 551 / 1,504 = **36.6%** |
| C1（+1/+86）命中 | 0（由区号护栏决定，非安全性证据） |
| **C3（真实用户）命中** | **4** |
| 24h 命中中「正常用户」 | 1 / 551 = **0.181%** |
| 全攻击期命中中「正常用户」 | 4 / 3,470 = **0.115%** |
| 规避成本 | **极低** —— 黑产补发一个 token 即可绕过 |
| token 缺失后仍有效 | **是**（本条即为此设计） |
| token 无效后仍有效 | 否（无效 token 仍是 present） |
| 高分养号后仍有效 | 否 |

**4 条误伤样本已逐条打开**（`05_人工确认清单.md` B2 需 David 复核）：

| 时间 UTC | 区号 | IP 国家/城市 | 版本 | token | uid关联号数 | 标注 |
|---|---|---|---|---|---|---|
| 09-06 05:49 | +65 | 新加坡 Singapore | 1.4.16 | absent | 1 | 正常用户 |
| 09-07 07:24 | +65 | 新加坡 Singapore | 1.3.65 | absent | 1 | 正常用户 |
| 09-08 04:14 | +60 | 罗马尼亚 Fundeni | 1.4.42 | empty | 2 | 正常用户 |
| 09-12 08:24 | +852 | 中国 香港岛 | 1.3.32 | absent | 1 | 正常用户 |

**这 4 条的共同点是老版本客户端本来就不发 token**（1.4.16 / 1.3.65 / 1.3.32），不是黑产。这也正是 `strategy_bTCEWBZggaAP` 里带 `version 版本号大于等于 1.4.30` 护栏的原因。

⚠️ 但**加版本护栏的代价极大**：加上 `version 版本号大于等于 1.4.30` 后覆盖 A 从 41.5% 掉到 **7.1%**（因为 token 缺失的漏出里 82% 就在 1.3.40/1.3.50/1.4.26 这几个老版本上）。
→ **取舍交给人**：不加护栏，41.5% 覆盖 / 0.115% 误伤（略高于 SOP 0.1% 上限，样本 4 条）；加护栏，7.1% 覆盖 / 0% 误伤。本轮**建议不加版本护栏，但把这 4 条样本连同取舍一并提交审批**。

### 🟢 R3C2 —— 零真实用户的 IP 来源国家

```
(区号不是1&&区号不是+1&&区号不是86&&区号不是+86)&&cid 包含 105
&&realIpCountry 包含 德国,阿联酋,巴西,菲律宾,加拿大,瑞典,爱沙尼亚,智利 则 REJECT
```

名单入选条件（三条同时满足，避免拍脑袋）：24h 漏出量 ≥15 · 35 天内 OTP 填充数 **为 0** · 35 天境外 PASS 总量 ≥50。

| 指标 | 数值 |
|---|---|
| 覆盖 A | 340 / 1,247 = **27.3%** |
| 覆盖 B | 340 / 1,504 = **22.6%** |
| **C3（真实用户）命中** | **0** |
| 24h 命中中「正常用户」 | 0 / 340 = **0.000%** |
| 全攻击期命中中「正常用户」 | 0 / 4,599 = **0.000%** |
| 规避成本 | **中** —— 需更换托管商出口国 |
| token 缺失 / 无效 / 高分养号后仍有效 | **是 / 是 / 是**（完全不依赖 reCAPTCHA） |

🔴 **被明确排除在名单外的国家**，因为它们有真实用户：

| 国家 | 24h 漏出 | C3 真实用户 |
|---|---|---|
| 巴基斯坦 | 644 | **20** |
| 新加坡 | 61 | **59** |
| 罗马尼亚 | 29 | **11** |
| 英国 | 27 | **9** |

巴基斯坦漏出量最大（51.6%），但**有 20 条真实用户**，整国拉黑会误伤，本轮不纳入。172 已覆盖「巴基斯坦 + 低分」，其余部分留给聚合类兜底。

⚠️ 名单中 `加拿大 / 瑞典 / 爱沙尼亚 / 智利` 单国漏出量仅 19–21 条，证据较薄，需 D2 项人工确认后再定是否保留。

### 两条合并效果

| 组合 | 覆盖 A | 覆盖 B | 24h 新增拦截 | 召回 | 命中中正常用户 |
|---|---|---|---|---|---|
| 现状（仅在线策略） | — | — | — | 62.6% | — |
| + R3C1 | 41.5% | 36.6% | 549 | **76.5%** | 1 |
| + R3C2 | 27.3% | 22.6% | 339 | **71.2%** | 0 |
| **+ R3C1 且 R3C2** | **64.8%** | **55.9%** | **839** | **83.8%** | 1（0.119%） |

两条重叠很小（R3C1 的命中里仅 11% 同时命中 R3C2），**互补性好**。

**对 upush 境外日发送量的预估影响**（当前约 1,268 条/天）：

| 上线 | 预计境外日发送 | 降幅 |
|---|---|---|
| R3C1 | ≈ 803 | 37% |
| R3C2 | ≈ 981 | 23% |
| **R3C1 + R3C2** | **≈ 559** | **56%** |

🔴 **即使两条都上，559 条/天仍是 150 条目标的 3.7 倍。** 特征类策略这一轮能拿到的空间就这么多，剩余缺口需要靠 upush/Twilio 侧的地区权限或日上限来关（见 `04_` 第五节）。这一点不应被「召回 83.8%」的数字掩盖。

## 四、需新增特征（研发支持）及其价值

| 建议特征 | 可补覆盖 | 备注 |
|---|---|---|
| **uid 在请求时刻是否从未出现于其它场景** | A 中 98.4% vs C3 中 0.0% | 🔴 当前 98.4%/0.0% 是**事后口径**，高估实时表现；真实用户注册时同样是「首次出现」。必须由研发给出请求时刻可判定的定义，并重新评估对新用户的误伤 |
| `userAgent` 设备品牌/机型 | 近乎完美（漏出 Infinix/BE2028/vivo，真实用户 iPhone） | 引擎无 userAgent 特征 |
| 同 uid 近 N 分钟关联手机号个数 | A 中位 11 vs C3 中位 1 | 现有同类特征只有 IP 维度 |
| 手机号号码合法性（phonenumbers） | 已用于标注 | 引擎无此特征 |
| ASN / 机房 IP 标签 | 未量化 | 比 IP C 段更稳定，规避成本更高 |

## 五、三种突破方式下的存活性对照（段枝宏 2026-09-11 要求）

| 候选 | ① 黑产不再带 token | ② 带无效 token | ③ 高分养号 |
|---|---|---|---|
| 172 / 策略3 / 策略4（分数型） | ❌ 失效 | ❌ 失效（无效 token 仍是 present，且已无低分） | ❌ 失效 |
| **R3C1**（token 缺失/空） | ✅ 专为此设计 | ❌ | ❌ |
| **R3C2**（IP 来源国家） | ✅ | ✅ | ✅ |
| 速率/聚合兜底（现网 33 条） | ✅ | ✅ | ✅ |

**当前漏出的 58.1% 已经是「高分养号」形态**，只有 R3C2 与现网兜底对它有效。这是 R3C2 虽然覆盖率低于 R3C1、却同样建议上线的原因。
