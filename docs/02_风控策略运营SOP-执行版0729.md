## 一、SOP 流程标准要求

本 SOP 分为两个阶段执行：**配置前评估**和**发布前评估**。前者解决「这条策略该不该配、会不会配错」，后者解决「这条策略能不能正式上线、能不能扩范围」。

> **核心原则**：先评估、后配置；先观察、后上线；先审批、后扩范围；关键动作必须双人复核、全程留痕。

### 1.1 配置前评估

- 策略发起前必须明确策略目标、规则逻辑、阈值、时间窗口、处置动作和生效范围。
- 必须确认字段语义、字段取值来源和业务背景，避免近义字段、错误对象、错误时间窗口导致配置偏差。
- 必须识别潜在误伤风险，包括办公出口 IP、B 端接口、合作方调用、聚合设备、门店终端等特殊流量。
- 核心链路或高风险强拦截策略，配置前必须由 leader 审批通过后方可进入配置阶段【后续平台管控】。

### 1.2 配置后双人 Check

- 策略配置完成后，正式进入观察前必须完成双人 check。
- 复核人需独立检查规则逻辑、阈值、时间窗口、处置动作、生效范围及关联活动配置，不得仅口头确认。
- 双人 check 未完成，不得提交发布前观察【后续平台管控】。

### 1.3 配置后系统稳定性检查要求【预上线后】

- 策略完成配置后，必须第一时间检查宙斯报错大盘，确认平台侧未出现异常报错后，方可进入观察期。
- 宙斯报错大盘主要用于从系统稳定性角度识别配置错误、规则复杂度过高或触发系统 bug 等问题，不替代规则逻辑复核。
- 若宙斯报错大盘出现新增异常、报错突增或明显关联当前策略的异常日志，应立即停止后续发布动作，先排查并修复问题。
- 宙斯检查结果必须留痕记录，作为发布前评估的前置输入之一。

### 1.4 预上线观察期要求

- 策略默认先以观察模式运行，不得直接阻断上线。
- 观察期必须覆盖核心活跃时段、主要用户场景，以及活动高峰期或典型流量周期。
- 观察期未达到对应策略类型的最低要求，不得进入发布前审批【后面有要求】。

### 1.5 发布上线前评估要求

- 发布前评估必须综合判断观察覆盖、整体调用量、整体用户量、命中样本量、准确率和误伤比例，不得仅凭少量命中样本直接上线。
- 即使命中样本量较低，只要整体调用量、整体用户量和观察覆盖满足要求，且命中样本复核准确、未发现明显误伤，仍可作为上线依据。
- 若整体调用量或整体用户量基数过低，即使相对占比达标，也不得直接上线，需继续观察或走例外审批。
- 任何扩活动、扩接口、扩范围动作，必须重新评估，不得默认复用前次结论。

### 1.6 上线后监控与复盘要求

- 上线后必须指定监控责任人，持续关注命中量、误伤反馈、客服投诉、业务指标异常和扩范围影响。
- 若发现误伤、波动或评估结论与线上表现不一致，应立即回滚或降级，并启动复盘。
- 复盘需明确配置错误、评估失真、审批缺失、监控滞后等问题，并沉淀到后续规则和模板中。

### 1.7 审批与例外要求

- 配置前由 leader 确认是否可以配置；发布前由 leader 根据评估结果确认是否可以上线【后续平台管控】。
- 以下场景可申请例外审批：**低频接口、冷启动活动、正在遭受黑产攻击的紧急处置场景**。
- 例外审批必须说明**原因、风险、补充控制措施和上线后监控安排**；不得以「紧急」为由跳过双人 check 和事后复盘。

### 1.8 应急止损

- 在收到业务、客服、运营等反馈，或通过监控预警确认线上存在误伤时，应第一时间开展研判，快速判断是否为误拦截问题以及影响范围。
- 若评估属于误拦截问题，应第一时间**电话报备**并同步相关责任人，立即执行止损操作，不得仅采用飞书消息同步方式等待回复。
- 止损动作可包括但不限于：关闭策略、切回观察模式、缩小生效范围、停止扩范围、回滚至上一稳定版本。
- 应急止损完成后，需补充留痕记录，包括发现时间、确认时间、报备时间、止损时间、影响范围、处置动作和恢复情况。

## 二、发布前评估分级标准表

为避免发布前评估过于主观，正式上线必须同时满足观察时长、整体调用量、整体用户量、样本量、准确率和误伤比例要求。对于低频接口或紧急攻击场景，可走例外审批，但必须说明原因及补充控制措施。

| 策略类型 | 最低观察时长 | 最低整体调用量 | 最低整体用户量 | 命中样本参考门槛 | 最低准确率 | 最高误伤比例 |
|---|---|---|---|---|---|---|
| **普通策略** | 20 分钟 | 同时满足：近 7 日同期平均调用量的 70% 以上，且不低于 3000 次 | 同时满足：近 7 日同期平均用户量的 70% 以上，且不低于 1000 人 | 10 | 99.9% | 0.1% |
| **活动类策略** | 1 个活动核心周期 | 同时满足：近 7 日同期平均调用量的 70% 以上，或当前活动预估流量的 70% 以上，且不低于 5000 次；或者测试验证没问题 | 同时满足：近 7 日同期平均用户量的 70% 以上，或当前活动预估用户量的 70% 以上，且不低于 1500 人；或者测试验证没问题 | 10 | 99.9% | 0.1% |
| **高风险强拦截策略** | 30 分钟 | 同时满足：近 7 日同期平均调用量的 80% 以上，且不低于 8000 次 | 同时满足：近 7 日同期平均用户量的 80% 以上，且不低于 3000 人 | 20 | 99.9% | 0.1% |

- 命中样本量不是唯一依据。若命中样本较低，但整体调用量、整体用户量、观察覆盖情况已满足要求，且命中样本经复核准确、未发现明显误伤，仍可作为上线依据。
- 若近 7 日整体调用量本身较低，则不能仅用「相对占比达标」作为上线依据，必须同时满足绝对调用量和绝对用户量门槛；否则只能走例外审批。
- 任何扩活动、扩接口、扩用户范围动作，都应视为新的发布动作，重新开展发布前评估，不得沿用原评估结论直接扩范围。

## 三、黑产评估标准

黑产评估用于判断策略命中样本是否真实属于黑产、作弊、代下或异常攻击行为。评估结论应作为策略准确率评估和上线审批的重要依据。原则上不得仅凭单一特征直接定性，应结合行为特征、资源特征、链路特征、身份特征和设备特征综合判断。

### 3.1 代下行为特征

判断点：

- 用户历史下单地市是否明显分散，超出正常个人消费半径。
- 若历史下单集中在同一地市，涉及店铺是否明显分散，超出正常用户常去门店范围。
- 短时间内是否在多个地市、多个区域门店产生下单行为。
- 下单门店分布是否与用户历史常驻地、常用门店、常规消费轨迹明显不一致。
- 是否存在账号归属相对稳定，但订单落点频繁变化的异常模式。

**结论口径**：若用户历史下单地市明显分散，或虽集中于同一地市但店铺分布异常分散，且不符合正常用户消费习惯，可判定存在较强代下嫌疑；若同时叠加设备、IP、链路等其他异常特征，可进一步提升为高疑似黑产或确认黑产。

### 3.2 IP / 设备聚集特征

判断点：

- 同一 IP 是否关联多个账号、多个手机号或多个设备。
- 同一设备是否关联多个账号、多个手机号或多次重复参与核心活动。
- 是否存在短时间内同一 IP、同一设备高频触发相同行为。
- 是否存在代理 IP、机房 IP、异常地域跳变或不符合真实用户分布的访问来源。
- 是否存在账号、IP、设备之间明显的一对多、多对一或多对多聚集关系。

**结论口径**：若 IP、设备、账号之间存在明显聚集关系，且超出正常合理范围，可视为强辅助证据；若同时叠加行为异常、链路异常或高风险标签，可进一步提升黑产判断置信度。

### 3.3 手机号风险特征

判断点：

- 是否命中猫池号、高风险号段、虚拟运营商高风险标签或其他内部风险标签。
- 是否存在批量注册、批量领券、批量下单、批量参与活动等历史记录。
- 是否与多个高风险设备、异常 IP、可疑账号存在强关联关系。
- 是否存在频繁更换账号主体但持续使用同类手机号资源的情况。
- 是否与历史已确认黑产样本存在明显相似特征。

**结论口径**：手机号命中猫池号或高风险标签时，可作为强风险辅助特征；原则上不建议仅凭手机号单一维度直接认定为黑产，应结合行为、链路、设备等其他证据综合判断。

### 3.4 API 链路异常特征

判断点：

- 是否高频单独请求某个核心接口。
- 是否跳过正常前置页面、前置接口或关键校验环节。
- 是否存在请求路径不完整、调用顺序异常或上下文缺失的情况。
- 是否呈现固定时间间隔、高频重试、脚本化调用等自动化行为特征。
- 是否存在只请求收益接口、不走正常浏览和转化链路的行为。
- 是否存在接口组合异常、访问顺序异常或链路明显偏离正常用户路径。

**结论口径**：若 API 调用链路明显不符合正常用户操作路径，且呈现自动化、脚本化、高频化特征，可作为黑产判断的重要依据；若同时叠加 IP/设备聚集、高风险手机号或高风险设备标签，可进一步提高黑产判断置信度。

### 3.5 设备指纹风险特征

判断点：

- 设备指纹是否命中高风险标签。
- 是否存在模拟器、改机、Root、越狱、虚拟环境等异常环境特征。
- 是否存在同一设备频繁切换账号、频繁变更身份主体的情况。
- 是否存在设备环境参数异常一致、批量复制或批量伪造痕迹。
- 是否与历史已确认黑产设备画像高度相似。

**结论口径**：设备指纹命中高风险环境标签时，可作为强辅助判断依据；若同时伴随链路异常、IP 聚集或账号聚集等特征，可显著提升黑产判断置信度。

### 3.6 礼品卡转赠异常特征

判断点：

- 同一用户是否频繁接受转赠礼品卡，明显高于正常用户水平。
- 同一用户是否频繁发起转赠礼品卡，形成高频转出行为。
- 转赠关系是否呈现集中化特征，例如少量账号反复向大量账号转赠，或大量账号反复向少量账号转赠。
- 礼品卡转赠后是否快速被消费、再次转赠或集中核销。
- 转赠行为是否与用户历史消费习惯、社交关系、账号活跃特征明显不匹配。
- 是否与高风险设备、异常 IP、代下账号或其他黑产标签存在关联。

**结论口径**：若同一用户频繁接受转赠，或频繁发起转赠，且明显超出正常礼品赠送场景，可判定存在较强礼品卡黑产嫌疑；若同时伴随设备聚集、链路异常、账号关联集中、快速转出转入等特征，可进一步提升为高疑似黑产或确认黑产。

### 3.7 黑产评估统一原则

1. **不得仅凭单一特征直接定性。** 除已验证高置信标签外，原则上不得仅凭单一维度直接认定为黑产。
2. **一般应至少具备两类及以上风险特征交叉印证**，才可判定为「确认黑产」或「高疑似黑产」。
3. **优先看行为，再看资源，再看标签。** 行为异常是核心判断依据，IP、设备、手机号、标签等属于辅助增强证据。
4. **证据不足不得强行归因。** 无法形成稳定证据链的样本，应标记为「暂无法判断」，不得为提升准确率而主观归类为黑产。

### 3.8 黑产评估结论分级

- **确认黑产**：已有明确证据，且至少两类以上风险特征交叉印证，基本排除正常用户可能。
- **高疑似黑产**：存在较明显异常特征，但证据链尚未完全闭环。
- **正常用户**：行为、资源、链路和身份特征符合正常用户特征，或已有证据证明属于误伤。
- **暂无法判断**：当前证据不足，无法形成稳定结论。

## 四、执行模板一：配置前评估表（建议建为多维表格）【后续平台管控】

用途：用于判断策略是否可以进入配置阶段，重点防止规则本身设计错误、对象理解错误和误伤风险未识别。

| 字段名 | 字段类型 | 必填 | 填写说明 / 示例 |
|---|---|---|---|
| 策略名称 | 单行文本 | 是 | 策略唯一名称 |
| 所属场景 | 单选 | 是 | 营销 / 注册 / 下单 / 活动 / 账号安全 |
| 接口 / 对象 | 单行文本 | 是 | 明确针对哪个接口或行为对象 |
| 配置人 | 成员 | 是 | 策略负责人 |
| 策略目标 | 多行文本 | 是 | 要解决什么风险问题 |
| 上线原因 | 多行文本 | 是 | 为什么现在要上这条策略 |
| 规则逻辑 | 多行文本 | 是 | 如 7 天内同一手机号关联会员 ID>2 |
| 阈值说明 | 多行文本 | 是 | 阈值是多少、依据是什么 |
| 处置动作 | 单选 | 是 | 观察 / 验证 / 提醒 / 拦截 / 降级 |
| 生效范围 | 多行文本 | 是 | 活动、接口、用户范围 |
| 字段语义是否确认 | 单选 | 是 | 是 / 否 |
| 字段取值来源是否确认 | 单选 | 是 | 是 / 否 |
| 是否存在近义字段混淆风险 | 单选 | 是 | 是 / 否 |
| 接口类型判断 | 单选 | 是 | C端 / B端 / 混合 |
| 是否存在正常聚合流量风险（IP、设备、账号等） | 单选 | 是 | 是 / 否 |
| 是否已了解接口业务背景 | 单选 | 是 | 是 / 否 |
| 是否识别潜在误伤人群 | 单选 | 是 | 是 / 否 |
