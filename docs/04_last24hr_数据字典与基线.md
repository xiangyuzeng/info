## 3. `策略命中` 列定义（26 列，主表没有的字段用 ★ 标注）

`access_time` · `cid` · ★`access_id`(=LKUS) · `scene_id` · `user_no` · `country_code` · `phone_no` · `ip` · `ip_country` · `version` · ★`realIp` · ★`uid`（网关 uid，设备/会话标识） · ★`userAgent`（如 `luckin coffee/1.4.42 (Infinix X6725; Android 15; Scale/1.75)`） · ★`couponNames` · ★`orderPrice` · ★`shopCityName` · `resultCode` · `resultName` · `message` · ★`bestStrategyId` · ★`hitStrategy`（命中的全部 ONLINE 策略，含 status/strategyId/strategyName） · ★`bestPreOnlineStrategyId` · ★`hitPreOnlineStrategy` · ★`hitBreakStrategy` · ★`featureDetail` · ★`ruleDetail`（**每条规则的 true/false 结果 —— 有它就能回测任意规则组合，不必重新实现特征**）

> **给 Claude Code 的任务**：这些 ★ 字段在数据库里大概率藏在 `extend` / `req_detail` 的 JSON 里，或在独立的命中日志表中。Phase 0 必须把它们定位出来，否则设备维度（`uid`、`userAgent`）分析无从做起。

关键事实：`ip == realIp` 的比例 **100%**（2,265/2,265）—— 不是 CDN 或代理头解析问题。

## 5. 时区判定

`country_code=1`（正常美国用户）的逐小时分布：UTC T12–T18 为高峰，T00–T06 近零。若按 UTC−4（EDT）换算，高峰落在 08:00–15:00 EDT，符合美国作息 → **`access_time` 字段为 UTC**。

同一换算下：

- 非 +1 流量：EDT 19:00–13:00 持续活跃，15:00–18:00 近零
- +1 流量：EDT 07:00–15:00 高峰

**结论**：报告中做时段分析必须换算到 EDT（业务与 Grafana 都是 EDT），并同时标注北京时间给国内同事看。Claude Code 需在 Phase 0 用 `NOW()` 与 Grafana EDT 总量二次验证这一判定。
