# 02 · 看板设计说明（改版前必读）

> 读这份是为了：改版时不把已经定下来的决策改漂。每条都写了**为什么**，
> 你可以推翻，但请先看清代价。

## 受众与体裁

- **受众**：中国总部安全/技术管理层。不是风控同学，不是 DBA。
- **体裁**：这是一块**看板（被扫视和据以决策）**，不是一篇报告（被从头读到尾）。
  所以：结论在最上面、状态用形状不只用数字（红色状态条、pill 标签）、明细收进折叠区。
- **组织逻辑**：不是把技术稿翻译一遍，而是按管理层真正会问的四个问题重排 ——
  **花了多少钱 / 有没有伤到真实用户 / 压制住没有 / 要我批什么**。

## 色板

| 用途 | 亮色 | 暗色 | 说明 |
|---|---|---|---|
| chrome（表头、结构） | `#1F3864` | `#8FB0E0` | 公司月报品牌深蓝，保持与既有管理层材料的视觉延续 |
| 数据色·正常用户 | `#2a78d6` | `#3987e5` | 已过色板校验 |
| 数据色·攻击流量 | `#eb6834` | `#d95926` | 已过色板校验 |
| 语义·危险 | `#C0342E` | `#F08C86` | 状态条、危险 KPI |
| 语义·良好 | `#1E7A4C` | `#63C795` | 「正常用户影响 0」「已避免损耗」 |
| 语义·警告 | `#B8730F` | `#E5A548` | 拦截率（未达标但非危险） |
| 中性 | 见 `dashboard.py` 的 `:root` | | 冷调偏蓝的灰，不是纯灰 |

**为什么数据色不直接用品牌深蓝 `#1F3864`**：图表数据色需要落在明度带内才能保证可辨识，
品牌深蓝太暗，过不了校验。因此**结构用品牌色、数据用校验过的色** —— 这是有意的分工，不是疏漏。

**校验记录**：`#2a78d6,#eb6834` 在亮色下全部通过（最差相邻色盲对 ΔE 9.2，正常视觉 ΔE 27.6）。
若你要换数据色，请重新跑 `dataviz` 技能里的 `scripts/validate_palette.js` 再定。

## 字体

- 中文正文与标题：**Noto Sans SC**（Google Fonts），层级只靠字重（400/500/700/900）和字号拉开。
- 数字：**IBM Plex Mono** + `font-variant-numeric: tabular-nums`，KPI 与表格数字对齐。
- 回退栈：`"PingFang SC","Microsoft YaHei",system-ui,sans-serif`。

**为什么不加第二套中文字族（例如衬线体做标题）**：CJK 字体文件很大，而管理层多在**手机、
飞书/微信内置浏览器**里打开，多加一套会明显拖慢首屏。用字重分层是这里更正确的取舍。

## 主题（三态，容易写错的地方）

viewer 有三种状态：未标记（跟随系统）/ `data-theme="light"` / `data-theme="dark"`。

- 亮色全套 token 定义在**裸 `:root`**；
- `@media (prefers-color-scheme: dark)` 里用 `:root:not([data-theme="light"])` 只重定义 token；
- `:root[data-theme="dark"]` 再重定义一次，保证手动切换双向都赢。

🔴 **绝对不要在 media 或 `[data-theme]` 块里直接给组件写色值。**
表头文字色曾经就是这么写的，导致三态里有一态是深字压深底。修法是加 `--on-navy` token —— 
**任何"这个颜色在两个主题里要反过来"的需求，都应该新增一个 token，而不是新增一条主题作用域的组件规则。**

## 图表

内联手写 SVG（Artifact 的 CSP 禁止外部 JS/CSS，**不能用任何图表库**）。坐标在 Python 里算好。

- 趋势图：2px 线、末点加实心圆点 + 数值直标、虚线标注措施时间点、网格线用 `--line` 弱化。
- x 轴标签每 3 天一个；末尾那个标签**只在与前一个间隔 ≥2 个位置时才加**，否则会和倒数第二个挤在一起（已修过一次）。
- 填充率图：两条水平条 + 大号数值直标；0.6% 的条宽有 3px 下限，否则看不见。
- 图例：≥2 个系列必须有图例；单系列不放图例（标题已经说明了是什么）。
